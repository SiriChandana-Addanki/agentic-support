# Architecture
`TicketContext → Retriever → Planner → ActionPlan → PolicyEngine → PolicyDecision → Tools → ToolResult → Resolution` is the execution boundary. Planner output is typed, validated and retried before any tool runs. It proposes actions and does not execute or authorize them. Policy independently applies business rules; tools receive `ToolContext`, not raw planner authority, and validate ownership, account status, lifecycle, dates, evidence, stock, serviceability, idempotency, and action-specific transitions.

Duplicate cancellation reads the customer's orders, confirms matching processing orders, and targets only the later one. The cancellation tool independently rejects a duplicate-target request unless another matching processing order exists and the target sorts as later. Already-cancelled requests read status and perform no write. Repeated order-read failures retry to a bounded limit then create an escalation; an expected malformed read can recover on retry. Cancellation timeout recovery re-reads state before deciding whether to retry.

The evaluator is fixture-specific by design, but its state logic uses action and state invariants rather than ticket IDs. Stability fingerprints include final state. Failed write attempts do not count as duplicate successful mutations. The API remains development-only and unauthenticated. Traces are sanitized operational records, not customer-facing endpoints. This repository does not claim production readiness, an LLM planner, semantic RAG, or production authentication.
