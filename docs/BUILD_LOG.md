## 2026-10-04 — interchangeable LLM planner

Recorded the pre-change reference at `reports/deterministic_baseline_2026-10-04.json` (114/114 strict rows, 38/38 stable tickets, 19 tests at commit `2c36765`). Added a shared typed planner protocol, retained the deterministic planner as default, and implemented an optional LLM planner behind a provider protocol using standard-library HTTP and structured JSON Schema output. Strict local parsing rejects unknown tools, direct refunds, wrong write flags, unsupported combinations, malformed/extra fields, order-reference injection, and unsafe summaries before PolicyEngine runs. Provider failure falls back to deterministic planning; repeated invalid output uses a locally constructed validated escalation plan. Added optional shadow mode.

The LLM receives serialized untrusted ticket/context fields and typed lexical evidence, never Store records or reviewer-only fields. Trace/resolution distinguish proposal, policy-authorized action, actual tools, provider/model/request metadata, attempts, validation, fallback, latency, and token usage where exposed. Estimated cost is null. Added mock-provider tests for valid, malformed, invalid, hostile, wrong-reference, timeout, and provider-error cases. Stock checks and replacement execution now rely on store stock state, and replacement evidence must match the ticket attachment manifest.
